# Cumulative enterprise GenAI disclosure benchmark

This repository contains the synthetic enterprise interaction benchmark, labelling code, detection models and evaluation results accompanying the study on cumulative enterprise data leakage and attack-ready disclosure states in generative AI. 

The article is published by Scientific Reports:

### Detecting Attack Readiness from Cumulative Enterprise Data Leakage in Generative AI


The main benchmark contains 15,000 sessions and 92,791 prompts, organised into three profiles.

| Profile | Sessions | Prompts | Attack-ready sessions |
| --- | ---: | ---: | ---: |
| Realistic | 5,000 | 27,556 | 9.9% |
| Balanced | 5,000 | 30,783 | 23.6% |
| Risk-Enriched | 5,000 | 34,452 | 53.8% |

The principal model comparisons use the Balanced profile. Data were generated synthetically; they do not contain actual company conversations.

## Files

- `data/profiles/`: raw and labelled interaction records, dataset statistics and labelling audits for the three benchmark profiles.
- `data/company.json`: generated enterprise entities used by the benchmark generator.
- `data/phase3_model_comparison_leakage_safe/`: seed-42 model checkpoints, evaluation metrics and predictions.
- `data/multiseed_leakage_safe/`: per-seed evaluation results and the five-seed statistical summaries used for the main performance comparison. Checkpoints for the other seeds can be regenerated by the training script.
- `data/ablation_leakage_safe/`: order-shuffling and feature-ablation results.
- `data/hard_generalisation/`: holdout and cross-profile evaluations.
- `data/remaining_validation/`: security baselines, client-side profiling, intervention thresholds and the final robustness results (`robustness_results_v2.csv`).
- `data/llm_rag_comparator/`: local instruction-model and retrieval-augmented comparator results.
- `data/validation_reference/`: the separate 31,835-prompt labelled cohort used for the expert-assessment sample and the reported label-sensitivity analysis, together with blinded sample data, anonymised decisions, label keys and aggregate statistics. This is not one of the three main benchmark profiles.
- `data/attack_simulation/`: the separate 1,500-session simulation inputs, per-session exposure scenarios and aggregate results used for the manuscript’s leakage-condition comparison.


## Environment

Python 3.10 or later is recommended. Install the main dependencies with:

```bash
python -m pip install -r requirements.txt
```

The local instruction-model comparison additionally requires:

```bash
python -m pip install -r requirements-llm.txt
```

Its first run downloads `Qwen/Qwen2.5-1.5B-Instruct` from Hugging Face. The associated model weights are not bundled here.

## Benchmark generation

Run the following commands from the repository root:

```bash
python main_phase1b.py
```

The generator uses the same company specification and profile seeds as the released benchmark: Realistic 43, Balanced 42 and Risk-Enriched 44. The provided JSON files can be used directly without regenerating the benchmark.

## Model training and evaluation

```bash
python train_phase3_model_comparison_leakage_safe.py --profile balanced --seed 42
python run_multiseed_statistics.py
python run_ablation_suite_leakage_safe.py
python run_hard_generalisation_splits.py
```

The main comparison evaluates prompt-level logistic regression, cumulative-history logistic regression, cumulative logistic regression with five structured features, GRU, BiLSTM and Transformer models. Splits are at session level, and the repeated-seed evaluation uses seeds 42, 52, 62, 72 and 82.

The leakage-safe structured features are turn index, newly introduced entity count, newly introduced entity-type count, cumulative entity count and cumulative entity-type count. Attack-template completion scores and target-derived contextual features are not included as model inputs.

For the additional robustness, enterprise-security baseline and intervention analysis:

```bash
python run_remaining_validation.py \
  --balanced data/profiles/balanced/prompt_sessions_labeled.json \
  --realistic data/profiles/realistic_mixture/prompt_sessions_labeled.json \
  --risk data/profiles/risk_enriched/prompt_sessions_labeled.json \
  --gru data/phase3_model_comparison_leakage_safe/gru_sequence.pt \
  --bilstm data/phase3_model_comparison_leakage_safe/bilstm_sequence.pt \
  --transformer data/phase3_model_comparison_leakage_safe/transformer_sequence.pt
```

The final entity-obfuscation and entity-extraction-failure conditions were generated using `run_robustness_v2.py` with the same inputs.

To run the instruction-tuned LLM comparator on the full test partition:

```bash
python run_llm_rag_comparator.py \
  --balanced data/profiles/balanced/prompt_sessions_labeled.json \
  --gru data/phase3_model_comparison_leakage_safe/gru_sequence.pt \
  --sample-size 0
```

## Expert assessment and sensitivity

The recorded 150-case expert-assessment sample and its three anonymised binary ratings are in `data/validation_reference/`. To reproduce the sensitivity calculations, use:

```bash
python label_validation.py sensitivity \
  --input data/validation_reference/prompt_sessions_labeled.json \
  --outdir data/validation_reference
```

To reproduce the expert agreement statistics, put the existing completed-rating file and framework key together (as provided), then run:

```bash
python label_validation.py analyse-expert \
  --input data/validation_reference/expert_validation_completed.csv \
  --out data/validation_reference/expert_validation_results.json
```

The expert assessment and sensitivity cohort predates the final three-profile calibration. These results are retained separately so their reported values can be reproduced from the data actually used.

## Attack simulation

The inputs and outputs corresponding to the manuscript's leakage-condition comparison are in `data/attack_simulation/`. This earlier 1,500-session experiment is distinct from the main three-profile benchmark. To regenerate its reported results from the labelled input records:

```bash
python -c "from src.attack_simulation import run_attack_simulation; run_attack_simulation('data/attack_simulation/prompt_sessions_labeled.json', 'data/attack_simulation/attack_simulation_sessions.json', 'data/attack_simulation/attack_simulation_summary.json')"
```

The script uses the scenario scoring model from the earlier attack-simulation evaluation. These simulation results are reported as framework-internal measures, not independent evidence of real-world attack prevention.

## Reproducibility

The benchmark generation, main metrics and key supporting analyses can be checked with:

```bash
python verify_release.py
```

The repository includes the original reported metrics and model weights where identifiable. Performance can vary across hardware, software versions and stochastic training runs. Inference-latency measurements are hardware-specific.
